# Patterns (linear + circular): feature plan

Plan for the Phase 5 "Linear pattern (1- and 2-direction), circular pattern
(axis + count + angle)" item in PLAN.md. Covers scope (sketch vs body), the
document model, inputs, dialog UX, kernel work, previews, MCP parity, and
phasing.

## 1. Scope: sketches AND solids — yes, both

Pattern should exist at both levels, exactly like Mirror already does
(sketch-level `DerivedOp` mirror + body-level `MirrorFeature`):

- **Sketch pattern** — a new associative `DerivedOp` (like offset/mirror),
  regenerated by `applyDerived` on every solve/regen. This is the *idiomatic
  way to replicate cut features*: open-poly's architecture is body-centric
  (mirror/transform target whole bodies, there is no "pattern this hole
  feature" like SolidWorks), so a bolt circle is made by circular-patterning
  the hole circle **in the sketch**, then doing a single extrude-remove.
  Derived entities participate in region detection (mirror outputs already
  do), so patterned profiles extrude naturally.
- **Body pattern** — a new timeline `PatternFeature` that replicates a built
  body via rigid transforms (`applyTrsf`), like Mirror/Transform-copy. For
  repeating whole parts: fence posts, gear-tooth blanks, a bolt itself.

Neither substitutes for the other: sketch patterns can't repeat a filleted 3D
body; body patterns can't cheaply repeat 40 holes (40 solids + 40 booleans vs
one region-rich sketch and one cut).

## 2. Sketch pattern (DerivedOp)

### Document model (`document/types.ts`)

```ts
export type DerivedOp =
  | ...existing offset / mirror / project...
  | {
      id: string;
      kind: "linearPattern";
      sourceIds: string[];          // hand-authored entities being repeated
      count: string;                // expression, TOTAL instances incl. seed (≥2)
      dx: string; dy: string;       // per-step vector in sketch u/v (expressions, mm)
    }
  | {
      id: string;
      kind: "circularPattern";
      sourceIds: string[];
      center: PointRef | { at: Vec2 }; // associative point ref preferred; raw uv fallback
      count: string;                // expression, TOTAL instances incl. seed (≥2)
      angle: string;                // total sweep in degrees; "360" = full circle
      symmetric?: boolean;          // spread ±angle/2 about the seed (ignored at 360)
    };
```

Notes:

- **Count includes the seed** (count 6 ⇒ seed + 5 copies) — matches
  Onshape/SolidWorks and is what users expect. Enforce ≥2 (a count of 1 op
  contributes nothing, same "never throws" policy as other ops).
- **No radius input for circular.** The user picks a *center*; each instance
  is the seed rotated about it, so the radius is implicit in where the seed
  already sits. (This matches every mainstream CAD; an explicit radius would
  fight the seed's position.)
- **Angle semantics** mirror revolve: full-circle mode is just `angle: "360"`
  with instances at 360/count steps (no duplicate at the wrap); angle mode
  spreads count instances evenly across the total angle, endpoints inclusive
  (step = angle/(count−1)); `symmetric` centers the spread on the seed.
- `center` as a `PointRef` (entity vertex / circle center / sketch origin)
  keeps the pattern associative when the referenced point moves. Clicking
  empty space drops a construction point at the click and references it, so
  the center stays draggable/dimensionable.
- Implementation is pure 2D math in `applyDerived`: a `rotateEntity` sibling
  to `mirrorEntity` in `sketchTools.ts` (rotate line/circle/arc/point about a
  uv point; arcs rotate start/end angles) and a translate helper. Output ids
  `${op.id}:${srcIndex}:${instanceIndex}` for stable identity across
  recomputes. Splines/text: exclude in v1 (mirror handles only
  line/circle/arc/point today too — keep parity).
- Deleting a generated entity removes the whole op; deleting a source removes
  the op — existing `DerivedOp` lifecycle rules apply unchanged.

### Sketch UX

One new toolbar entry in the sketch bar, a **flyout group like rect/circle**
with two variants (matches `SKETCH_GROUPS` precedent).

**Source accumulation** combines the two existing idioms, with the mirror
session as the chassis:

- The Select tool already toggle-accumulates (each click appends the pick to
  the selection or removes it if present — no Shift chord; empty-space click
  clears). **Activating a pattern tool with entities selected seeds the
  session from `selectedSketchEntities`** (the way Offset consumes the
  selection), then clears the selection.
- With nothing pre-selected the tool behaves like Mirror: the session starts
  empty and **each click adds an entity to `sourceIds`** (live ghost previews
  of all N−1 copies update per pick), **re-clicking a source toggles it off**,
  and a floating panel shows the running count ("3 in pattern — click
  entities to add"). Enter (or the panel button) commits the `DerivedOp` and
  re-solves (`solveSketchIn`, per `commitMirror`); Esc cancels.
- **Eligibility:** hand-authored entities only — `applyDerived` restricts op
  sources to non-`derivedFrom` entities so derivations can't chain, so
  clicking a mirrored/offset/projected output flashes a message rather than
  adding it. Construction entities are allowed; each copy preserves its
  source's construction flag.

Per-variant flow on top of that:

- **⁙ Linear pattern** — no arming click (direction isn't picked): pure
  accumulation, with a `dim-input`-style dialog (the small `DraggableDialog`
  used by offset/dimensions) showing **Count**, **Step X**, **Step Y**;
  dragging in the viewport sets the step vector directly (like offset's
  drag), typing refines it.
- **⁛ Circular pattern** — keeps Mirror's arm-first step for code symmetry:
  the **first click sets the center** (snapping to entity points / origin;
  empty space drops a construction point and references it), subsequent
  clicks accumulate entities. A seeded session (pre-selection) goes straight
  to the center click. Dialog shows **Count**, **Full ⟷ Angle** toggle,
  **Angle (°)** and **Symmetric** in angle mode, with live ghosts.

Both store the op and let `applyDerived` own the output from then on. Editing
an existing pattern (changing count/step later) goes through the same route as
offset today (re-open via clicking a generated entity is a future refinement;
v1 minimum: delete + redo, and expression-backed values editable wherever
`DerivedOp` params surface).

## 3. Body pattern (PatternFeature)

### Document model

One feature type with a `kind` discriminant (like `PlaneFeature.method`):

```ts
/** A direction for a linear pattern: a world axis, a sketch line, or a linear
 *  body edge (persistent name + fingerprint, like EdgeRef). */
export type PatternDirRef =
  | { world: "x" | "y" | "z" }
  | { sketchId: string; entityId: string }          // a line entity
  | { edge: { featureId: string; name: string; mid?: [number,number,number]; length?: number } };

/** A circular-pattern axis: a sketch line, a world axis, or a body face
 *  (cylindrical/conical face → its own axis; reuses revolve's face machinery,
 *  minus the plane∩profile variant, which needs a profile plane patterns
 *  don't have). */
export type PatternAxisRef =
  | { world: "x" | "y" | "z" }                       // through the origin
  | { sketchId: string; entityId: string }
  | { face: RevolveAxisFace };

export interface PatternFeature extends FeatureBase {
  type: "pattern";
  kind: "linear" | "circular";
  /** The body being repeated (feature id that produced it). Single seed in v1. */
  targetId: string;

  // -- linear --
  dir1?: PatternDirRef;
  count1?: string;      // expression, total instances incl. seed (≥2)
  spacing1?: string;    // expression, mm, instance-to-instance
  flip1?: boolean;
  dir2?: PatternDirRef; // optional second direction ⇒ count1×count2 grid
  count2?: string;
  spacing2?: string;
  flip2?: boolean;

  // -- circular --
  axis?: PatternAxisRef;
  count?: string;       // expression, total instances incl. seed (≥2)
  /** Total sweep in degrees ("360" = full circle, equal 360/count steps).
   *  In angle mode instances span the angle endpoints-inclusive. */
  angle?: string;
  /** Angle mode only: spread ±angle/2 to both sides of the seed. */
  symmetric?: boolean;

  color: number;        // appearance of the produced copies
  opacity: number;
  hidden?: boolean;
}
```

Same input conventions as the sketch op: **count includes the seed**, **no
radius input** (implicit in the seed's distance from the axis; a seed *on* the
axis just spins in place — allowed, warn in preview), angle semantics
identical to revolve's Full/Angle + Symmetric.

### Kernel (`kernel/worker.ts`)

- Resolve `dir1/dir2/axis` at protocol-baking time like revolve does
  (sketch-line and world variants pre-baked to `origin/dir`; a face axis
  resolved in the worker against the built body via the existing
  `faceRevolveAxis` cylindrical/conical path).
- For each instance i = 1..N−1 build a `gp_Trsf` (SetTranslation /
  SetRotation) and run the seed through **`applyTrsf`** — the same rigid-motion
  path transform/mirror use, so persistent names re-key 1:1 per copy.
  Suffix each instance's names (`name` → `name~p{i}`) so downstream
  chamfer/up-to-face/boolean picks stay unambiguous (this is the PLAN.md
  "patterns multiply topology — re-stress naming" item).
- **Result shape: ONE body per pattern feature — a compound of the N−1
  copies, keyed by the pattern's feature id; the seed body is left untouched**
  (delete/suppress the pattern ⇒ back to just the seed, exactly like Mirror).
  Rationale: the whole pipeline assumes one body per feature id
  (`requireBody`, SolidsList, `features.find(f => f.id === targetId)` name
  lookups); synthetic per-instance ids (`${id}:3`) would leak into every one
  of those. Multi-solid STEP import already ships as one compound, so
  compounds are an accepted body shape. OCCT booleans accept compounds, so
  "pattern the tool, subtract the compound" works.
  *Future (not v1):* per-instance skip list, per-instance bodies, and a
  "fuse with seed" option collapsing everything to one solid.
- Caching: `contentKey(feature, [target.key])` (+ axis body's key when the
  axis is a face), same as mirror. Rigid transforms are cheap; no special
  cache needed beyond that.

### Body-pattern dialog UX

One **⁙ Pattern** toolbar button (modeling bar, next to ⇋ Mirror; shortcut
suggestion: `N` — A/P/R/T/M are taken). Opens a **type-first dialog** exactly
like the Plane dialog's method-first layout, on the standard
`extrude-dialog`/`DraggableDialog` chassis:

```
┌ Pattern ──────────────────────────────┐
│ Type   [ Linear ] [ Circular ]        │   ← mode buttons, like revolve Full/Angle
│                                       │
│ Body   Body 3               ✕         │   ← click-to-populate, prefilled from
│        (or [Select a body])           │      the current selection like Mirror
│                                       │
│ ── Linear ──────────────────────────  │
│ Direction  [World X ▾]  [⇄ Flip]      │   ← World X/Y/Z / Sketch line… / Edge…
│            (line/edge ⇒ arm a pick,   │      pick-arming like revolve's axis
│             "Click a line or edge…")  │
│ Count      [ 4        ]               │   ← expression field (incl. seed)
│ Spacing    [ 25       ] mm            │   ← instance-to-instance, expression
│ ▸ Second direction                    │   ← collapsed expander; opens the same
│                                       │      three fields for a count1×count2 grid
│ ── Circular ────────────────────────  │
│ Axis       [Select axis]              │   ← same arming UX as revolve: sketch
│                                       │      line, world axis, or cyl/cone face
│ Count      [ 6        ]               │
│ Extent     [ Full (360°) ] [ Angle ]  │   ← identical to revolve dialog
│   Angle (°)  [ 120 ]     (angle mode) │
│   Symmetric  [x]         (angle mode) │
│                                       │
│ ⚠ warnings (e.g. seed lies on axis)   │
│            [ Create ]  [ Cancel ]     │
└───────────────────────────────────────┘
```

Details:

- **Live ghost preview** while the dialog is open — but unlike revolve's
  throwaway-doc kernel round trip, a pattern preview needs **no kernel call**:
  clone the seed's existing `FeatureMesh` N−1 times with the instance
  transforms applied in three.js. Instant, exact (rigid motions), updates on
  every keystroke.
- All numeric fields are expression strings (`"holes"`, `"360/teeth"`),
  consistent with everything else; Enter commits, Esc cancels, same key
  handling as revolve.
- Full mode hides angle/symmetric (forced to 360/off), exactly as revolve
  forces symmetric off for full — no dead inputs.
- Validation before Create: count ≥ 2, spacing ≠ 0 (linear), axis present
  (circular); degenerate inputs disable Create with an `ed-warning` line.
- Editing after creation: the feature's params (counts, spacing, angle,
  symmetric, flip) surface in `ParamEditor` like every other feature;
  re-picking direction/axis re-opens the dialog (same as revolve's edit path).

### Answering the "center point + radius" framing

For the **circular body pattern** the center is not a point — it's an **axis**
(a point alone doesn't orient the rotation in 3D). Reusing revolve's axis
picker (sketch line / world axis / cylindrical face) gives that for free and
keeps the two dialogs feeling like siblings. **Radius is never an input** at
either level: instances are rotations of the seed about the axis/center, so
the radius is wherever the seed already is — an explicit radius would have to
move the seed, which no mainstream CAD does. The revolve-style
**Full ⟷ Angle + Symmetric** trio carries over verbatim, as the user suggested.

## 4. MCP / agent parity

- New `pattern_body` tool (target body id, kind, and the same fields as the
  dialog; axis/direction accept the scene-summary's entity/edge/face names).
- Sketch patterns via a `sketch_pattern` tool (or an extension of the existing
  sketch-editing tool set) taking entity ids + the op's params.
- `modeling-guide.md` gains a "repeat geometry" section: prefer sketch
  patterns for repeated cuts, body patterns for repeated parts; counts include
  the seed; no radius input.

## 5. Tests

- `derived.test.ts`: linear/circular op regeneration — counts, step math,
  360 no-duplicate-at-wrap, angle endpoints-inclusive, symmetric spread,
  associativity (move the center point ⇒ outputs follow), missing-source and
  count<2 ops contribute nothing.
- `sketchTools` rotate/translate entity helpers (arcs keep sweep direction).
- Worker-level: pattern of a box along world X (bbox spans), circular about a
  sketch line (instance centroids on the circle), name re-keying suffixes
  unique per instance, compound participates in a subtract.
- Regions: a circular-patterned hole circle yields N regions ⇒ one
  extrude-remove cuts N holes.

## 6. Phasing

1. **Sketch patterns** (pure TS: types, `applyDerived`, `sketchTools`
   helpers, tests) + sketch toolbar flyout & tool flows. Highest value/cost
   ratio; unlocks bolt circles immediately.
2. **Body linear pattern**: `PatternFeature` (linear fields), worker compound
   build + name suffixing, dialog (Linear side), mesh-clone preview.
3. **Body circular pattern**: axis resolution reuse, dialog (Circular side).
4. **Second linear direction** (grid) — dialog expander + worker loop nesting.
5. **MCP tools + modeling guide + PLAN.md** checkbox updates.
6. *Later:* multi-seed patterns, per-instance skip, fuse-with-seed option,
   pattern-of-pattern, direct-manipulation spacing drag in the viewport.
